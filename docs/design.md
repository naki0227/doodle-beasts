# 設計メモ: Doodle Beasts

## 一言で

みんなで分担して描いた絵が一体の生き物になり、CPU の敵の波と戦う協力ゲーム。絵の形がステータスと武器を決める。絵心は要らない。

## コンセプトの柱

1. **一つのものをみんなで作る。** 参加人数ぶんにキャンバスを分割し、頭・胴・腕・脚などの部位を各自が描く。制限時間が来ると全員の絵が合体して一体になる。合体の瞬間がこのゲームの見せ場で、そのままスクリーンショットになる。
2. **描いた形がそのまま性能になる。** 画像認識ではなく幾何学的な量で決める。描いている途中に「これは…槍？」「HP 高め」と判定が画面に出るので、外れても笑えるし、描き方を学べる。
3. **CPU に立ち向かう。** 合体した生き物はビヘイビアツリー（BT）で自動で戦う。プレイヤーは戦闘中も少しずつ回復するインクで壁・矢・回復の落書きを描いて支援する。拠点が落ちたら全員の負け。
4. **下手でも成立する。** ぐちゃぐちゃの落書きは角が多いので攻撃型、丸く塗りつぶせば硬い、など、どんな絵にも性格が出る。「上手い絵が強い」ではなく「描き方で性格が変わる」。
5. **AI を使わない、オフラインで動く。** 判定はルールなのでランニングコストがなく、サービス終了で遊べなくならない。非同期対戦でも公平。

## 絵の解釈

| 絵の特徴 | 決まるもの |
|---|---|
| 使ったインクの総量 | ステータスの総量（上限固定。形は「配分」だけを決める） |
| 鋭い角の数 | 攻撃力 |
| 横幅と高さの比 | 移動速度（横長は速い、縦長は遅いが硬い） |
| 左右対称の度合い | 防御力 |
| 線の閉じている割合 | 装甲 |
| 部位の位置関係 | 攻撃の届く範囲と当たり判定 |

武器の判定（武器の枠に描いたもの）:

| 絵の特徴 | 判定 |
|---|---|
| 細長くて先端が鋭い | 剣・槍（先端の角度で刺突か斬撃か） |
| 先に丸い塊がある | ハンマー・メイス |
| 短い突起がたくさん | 爪・棘 |
| 閉じた大きな面 | 盾 |
| 弧に線が渡っている | 弓 |
| どれにも当てはまらない | 「謎の武器」。全属性そこそこ |

インク総量をステータス総量にするのは、理想個体づくりが「棘だけの塊」に収束しないようにするため。総合力は誰でも同じで、相性と戦術で勝負が決まる。

## 入力と人数

- 参加は「ボタンを押して参加」方式。接続数の自動検出は Steam Input が幻のデバイスを出すことがあるので使わない。マウスの人も 1 人として参加できる。
- パッド描画: 左スティックでカーソル、右トリガーで描く、左トリガーで消す。倒した量で速度が変わり、軽く倒すと細かい線が引ける。
- 人数より入力装置が少ないときは、同じ部位の枠を一人ずつ順番に回す。画面は同じで順番が変わるだけ。一人のときも同じ流れで全部位を描く。
- Steam Deck はタッチ画面とトラックパッドで描ける。
- Remote Play Together は遠隔の人のコントローラーを別のパッドとして渡してくるので、パッド描画なら遠隔の友達も自分の枠に同時に描ける。ネットコードなしでオンライン協力が成立する。

## 立体化

描いた輪郭を厚みのある板に押し出し、角を丸める。紙粘土や段ボール工作の質感。Godot の SurfaceTool で生成する。
ゲームは 2.5D にする。生き物は 3D で表示し、移動・当たり判定・BT の索敵は平面上で行う。完全 3D にするとナビゲーション・カメラ・物理が全部 3D になって工数がおよそ倍になる。

## 段階計画

### 第 1 段階（Steam 初期リリース）

パッドで分割描画、合体、押し出しの立体化、武器判定、CPU の波との協力戦。ローカルと Remote Play Together。サーバーなし。これだけで一本のゲームとして成立させる。

優先順:

1. 描画中の判定表示と合体演出（競合の不満と本作の見せ場がここに集中している）
2. パッド描画と分割キャンバス、参加の仕組み
3. 絵から輪郭・ステータス・武器を出す解釈器（テスト可能な純粋関数にする）
4. 押し出しの立体化
5. 戦闘中の落書き支援（壁・矢・回復）
6. 敵の種類、波の手書きデータ、効果音とノックバック

### 第 2 段階（発売後の無料アップデート）

- アトリエ: 時間無制限の練習モード。判定と推定ステータスを常時表示。保存と共有コード。
- 公開ギャラリーと非同期対戦: 他人の個体（線の座標の列）をダウンロードして自分の端末の BT で戦わせる。リアルタイムのネットコードは不要。
- ランキングは「挑まれた回数と勝率」にして、強い個体だけでなく面白い個体も上に来るようにする。
- サーバーは `gojuon-minesweeper` で作った Supabase の構成を流用する。ステータスはクライアントの値を信用せず、サーバーでも線のデータから再計算して照合する。

### 第 3 段階

リアルタイムのオンライン協力・対戦。ホスト権威型。ホストだけが BT と波を動かし、位置と HP を配る。接続は GodotSteam の Steam Networking 中継。

## 不適切な絵への対応（第 2 段階で必要）

1. フレンド限定の共有には判定を入れない。公開ギャラリーとランキングだけを対象にする。
2. 公開申請時にサーバー側で線を画像に描き出し、分類 API で明らかなものを弾く。文字入力は名前欄だけにし、禁止語で弾く。
3. 一定数の通報で即座に非表示にし、あとで目視で確認する。
4. ユーザーが少ないうちは審査後公開にする。増えてから自動化の比率を上げる。

## Steam までの段取り

- Steamworks パートナー登録（1 タイトル 100 USD、売上 1,000 USD 到達で返金）。税務・銀行情報に数日かかるので早めに。
- ストアページは発売の 2 週間以上前に公開が必要。「近日登場」ページを縦切り完成の時点で出し、「絵心不要」「友達と一体を作る」「AI 不使用・オフライン可」を前面に、日英同時で出す。
- 体験版は 2027 年 2 月の Next Fest を目標にする。開始前にウィッシュリスト 1,000 件を超えておく。
- 価格は $9.99〜12.99（日本では 1,200〜1,800 円）。買い切り + 任意の DLC。
- ビルドは Godot の Linux / Windows エクスポートを SteamPipe で上げる。GL Compatibility レンダラーなので Steam Deck や古い PC でも動く。

## いまの骨組みでできること（戦闘の土台）

- ローカル 2 人（キーボード 2 組、またはゲームパッド 2 台）
- 拠点の HP・修理・ゲームオーバー・やり直し
- 無限ウェーブ。波 n の敵数は 3 + 2(n-1)、HP 倍率は 1 + 0.15(n-1)
- 敵 AI は BT。近くのプレイヤーを優先して追い、いなければ拠点へ向かう
- 見た目は `_draw()` の図形だけ

描画と合体を足すとき、敵と味方の生き物は同じ BT と同じ「移動・攻撃・被弾」の契約で動かす。味方 CPU も同じ仕組みで作れるので、一人のときは CPU と協力できる。

## 技術メモ

- 物理レイヤー: 1 = players, 2 = enemies, 3 = core。
- 座標系は 1280x720 固定、`canvas_items` ストレッチ。
- 入力は `src/game/input_setup.gd` が起動時に InputMap へ登録する。
- 乱数は `WaveManager.random_seed` で固定できる。
- 絵のデータは「線ごとの点の列」を正とし、ステータスも立体化もそこから毎回導出する。保存・共有・検証がすべてこの一つの形式で済む。
