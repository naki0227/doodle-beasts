# 設計メモ

## コンセプト

- 2人（将来 4人）で一つの拠点を守る。拠点が落ちたら全員の負け。
- 敵は CPU。波ごとに数と硬さが増える。プレイヤーは殴って倒すか、拠点を修理して耐える。
- 1セッション 10〜20 分を想定。倒れても数秒で復活するので、初心者を連れて遊びやすい。
- 「一つのものを作り上げる」要素は、拠点の修理から始めて、壁や砲台の建築へ広げる（後述）。

## いまの骨組みでできること

- ローカル 2人（キーボード 2組、またはゲームパッド 2台）
- 拠点の HP・修理・ゲームオーバー・やり直し
- 無限ウェーブ。波 n の敵数は 3 + 2(n-1)、HP 倍率は 1 + 0.15(n-1)
- 敵 AI はビヘイビアツリー。近くのプレイヤーを優先して追い、いなければ拠点へ向かう
- 見た目は `_draw()` の図形だけ。画像素材はまだ無い

## 次に足すもの（優先順）

1. **建築**: 資源を拾って壁・砲台を置く。拠点の周りに置けるグリッドを用意し、敵 BT に「壁があれば壊す」枝を足す。
2. **敵の種類**: 速いが脆い / 遅いが硬い / 遠距離。ツリーの差し替えだけで作れる構造にしてある。
3. **フィードバック**: 効果音、被弾のノックバック、画面揺れ。手触りが出ると一気にゲームらしくなる。
4. **ウェーブ設計**: 手書きの波データ（JSON か Resource）。無限生成はその後ろに残す。
5. **4人対応**: `input_setup.gd` に P3/P4 を足し、`main.tscn` にプレイヤーを増やすだけで動く設計になっている。

## オンライン化の段取り

1. **Steam Remote Play Together**: ローカル協力が遊べれば、ネットコードなしでフレンドとオンラインで遊べる。まずこれで Steam に出す。
2. **本物のオンライン同期**: ホスト権威型。ホストだけが BT と波を動かし、敵の位置・HP・拠点 HP を `MultiplayerSynchronizer` で配る。クライアントは入力だけ送る。
   - 接続は GodotSteam アドオンの Steam Networking 中継を使うとサーバー代がかからない。
   - BT は決定的である必要はない（ホストだけが評価するため）。
3. 匿名マッチングやレーティングは、`gojuon-minesweeper` で作った Supabase の構成を流用できる。

## Steam までの段取り

- Steamworks パートナー登録（1タイトル 100 USD、売上 1,000 USD 到達で返金）。税務・銀行情報に数日かかるので早めに。
- ストアページは発売の 2 週間以上前に公開が必要。「近日登場」ページを縦切り完成の時点で出す。
- ビルドは Godot の Linux / Windows エクスポートを SteamPipe で上げる。GL Compatibility レンダラーにしてあるので Steam Deck や古い PC でも動く。
- 体験版は Steam Playtest か Next Fest で配る。

## 技術メモ

- 物理レイヤー: 1 = players, 2 = enemies, 3 = core。敵同士・プレイヤー同士も押し合う。
- 座標系は 1280x720 固定、`canvas_items` ストレッチ。
- 入力は `src/game/input_setup.gd` が起動時に InputMap へ登録する。project.godot に手書きしない。
- 乱数は `WaveManager.random_seed` で固定できる。再現テストに使う。
