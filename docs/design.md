# 設計メモ: Doodle Beasts

## 一言で

みんなで分担して記録帳に描いたかたちが一体の獣としてよみがえり、霜の獣の波から金の駒を守る協力ゲーム。製品名は「はかり野」。
絵の形がステータス・戦い方・武器を決め、戦闘は自動で進む。プレイヤーの腕前は「どう描くか」に出る。絵心は要らない。

## 遊びの流れ

1. 記録帳を開く（初回 60 秒、2 回目以降 40 秒）。旅人 1 が「からだ」、旅人 2 が「ぶき」を同時に描く。描いている途中から、札に性格・目の数・ステータス・武器とその動きが出る。
2. 二人が封をするか時間切れで合体。線が金に変わり「かたち、よみがえる」。
3. 戦闘は自動。獣は性格と武器のとおりに動き、旅人二人は駒に近づいた霜を払い、傷んだ駒を直す。人は操作しない。
4. 波を守ると「第N波を守った」。インクが 400 増え、記録帳へ戻る。前の絵が残っているので、描き足すか描き直す。
5. 駒の HP は波をまたいで持ち越す。駒が凍ったら終わり。

見どころは「描いたものが、そのとおりに動く」こと。トゲを足せば突撃になり、目を足せば遠くに気づき、弓を描けば下がって射る。負けた理由が絵に返ってくるので、描き直す動機が生まれる。

## 性格と行動（自動戦闘のルール）

| 形 | 性格 | 動き |
|---|---|---|
| 角が多い | 突撃 | 見えるいちばん近い霜の獣へ飛びかかる |
| 横長 | 遊撃 | 駒に近い敵を先回りして叩き、一撃ごとに身を引く |
| 左右対称で閉じている | 守護 | 駒のまわり 240 以内に来た敵だけを打ち、ふだんは駒の前で見張る |
| どれでもない | 盾 | 駒と敵のあいだに割り込み、敵を引きつける（敵の索敵で近く見える） |

- **目:** 輪郭の内側の小さな閉じた形の数。見える範囲は 230 + 110 × 目の数。
- **武器の動き:** 弓は近づかれたら下がって射る。ハンマーは周り 80 の敵にも半分の傷。盾はそばにいると駒の傷を 4 割減らす。謎の武器はときどき気まぐれに歩きまわる。
- **旅人:** 駒のまわり 200 以内の敵を杖で払う → 駒が傷んでいれば直す → 持ち場で待つ。
- ツリーの組み立ては `src/game/behavior_builder.gd`、葉ノードは `src/ai/`。性格・目・武器の判定は `src/draw/shape_analyzer.gd`。

## 音

すべて `tools/audio/gen_audio.py` で手続きに合成した Ogg Vorbis（第三者の素材なし）。

| 音 | 中身 |
|---|---|
| bgm_ambient（タイトル・記録帳） | 64 秒の輪。D の持続音、風、竪琴（カープラス・ストロング法）の爪弾き、ときどき鐘 |
| bgm_battle（戦闘） | 100 BPM、48 秒の輪。枠太鼓、持続音、竪琴の反復音型、8 小節ごとの角笛 |
| 効果音 18 種 | ペンの擦れ（描いているあいだだけ鳴るループ）、封蝋、合体の鐘、獣の着地、武器ごとの打撃、弓、霜が砕ける、霜の出現、駒への傷、修理、波の角笛、時計、波を守った、ゲームオーバー など |

鳴らす窓口は `Sound`（静的クラス）、実体は自動読み込みの `SoundBus`（効果音の再生器を使い回し、BGM はクロスフェード）。

## コンセプトの柱

1. **一つのものをみんなで作る。** 参加人数ぶんにキャンバスを分割し、頭・胴・腕・脚などの部位を各自が描く。制限時間が来ると全員の絵が合体して一体になる。合体の瞬間がこのゲームの見せ場で、そのままスクリーンショットになる。
2. **描いた形がそのまま性能になる。** 画像認識ではなく幾何学的な量で決める。描いている途中に「これは…槍？」「HP 高め」と判定が画面に出るので、外れても笑えるし、描き方を学べる。
3. **CPU に立ち向かう。** 合体した生き物はビヘイビアツリー（BT）で自動で戦う。プレイヤーは戦闘中も少しずつ回復するインクで壁・矢・回復の落書きを描いて支援する。拠点が落ちたら全員の負け。
4. **下手でも成立する。** ぐちゃぐちゃの落書きは角が多いので攻撃型、丸く塗りつぶせば硬い、など、どんな絵にも性格が出る。「上手い絵が強い」ではなく「描き方で性格が変わる」。
5. **AI を使わない、オフラインで動く。** 判定はルールなのでランニングコストがなく、サービス終了で遊べなくならない。非同期対戦でも公平。

## 絵の解釈

| 絵の特徴 | 決まるもの |
|---|---|
| 使ったインクの総量 | ステータスの総量（上限固定。形は「配分」だけを決める） |
| 鋭い角の数 | 攻撃力 |
| 横幅と高さの比 | 移動速度（横長は速い、縦長は遅いが硬い） |
| 左右対称の度合い | 防御力 |
| 線の閉じている割合 | 装甲 |
| 部位の位置関係 | 攻撃の届く範囲と当たり判定 |

武器の判定（武器の枠に描いたもの）:

| 絵の特徴 | 判定 |
|---|---|
| 細長くて先端が鋭い | 剣・槍（先端の角度で刺突か斬撃か） |
| 先に丸い塊がある | ハンマー・メイス |
| 短い突起がたくさん | 爪・棘 |
| 閉じた大きな面 | 盾 |
| 弧に線が渡っている | 弓 |
| どれにも当てはまらない | 「謎の武器」。全属性そこそこ |

インク総量をステータス総量にするのは、理想個体づくりが「棘だけの塊」に収束しないようにするため。総合力は誰でも同じで、相性と戦術で勝負が決まる。

## 入力と人数

- 参加は「ボタンを押して参加」方式。接続数の自動検出は Steam Input が幻のデバイスを出すことがあるので使わない。マウスの人も 1 人として参加できる。
- パッド描画: 左スティックでカーソル、右トリガーで描く、左トリガーで消す。倒した量で速度が変わり、軽く倒すと細かい線が引ける。
- 人数より入力装置が少ないときは、同じ部位の枠を一人ずつ順番に回す。画面は同じで順番が変わるだけ。一人のときも同じ流れで全部位を描く。
- Steam Deck はタッチ画面とトラックパッドで描ける。
- Remote Play Together は遠隔の人のコントローラーを別のパッドとして渡してくるので、パッド描画なら遠隔の友達も自分の枠に同時に描ける。ネットコードなしでオンライン協力が成立する。

## 立体化

描いた輪郭を厚みのある板に押し出し、角を丸める。紙粘土や段ボール工作の質感。Godot の SurfaceTool で生成する。
ゲームは 2.5D にする。生き物は 3D で表示し、移動・当たり判定・BT の索敵は平面上で行う。完全 3D にするとナビゲーション・カメラ・物理が全部 3D になって工数がおよそ倍になる。

## 段階計画

### 第 1 段階（Steam 初期リリース）

パッドで分割描画、合体、押し出しの立体化、武器判定、CPU の波との協力戦。ローカルと Remote Play Together。サーバーなし。これだけで一本のゲームとして成立させる。

優先順:

1. 描画中の判定表示と合体演出（競合の不満と本作の見せ場がここに集中している）
2. パッド描画と分割キャンバス、参加の仕組み
3. 絵から輪郭・ステータス・武器を出す解釈器（テスト可能な純粋関数にする）
4. 押し出しの立体化
5. 戦闘中の落書き支援（壁・矢・回復）
6. 敵の種類、波の手書きデータ、効果音とノックバック

### 第 2 段階（発売後の無料アップデート）

- アトリエ: 時間無制限の練習モード。判定と推定ステータスを常時表示。保存と共有コード。
- 公開ギャラリーと非同期対戦: 他人の個体（線の座標の列）をダウンロードして自分の端末の BT で戦わせる。リアルタイムのネットコードは不要。
- ランキングは「挑まれた回数と勝率」にして、強い個体だけでなく面白い個体も上に来るようにする。
- サーバーは `gojuon-minesweeper` で作った Supabase の構成を流用する。ステータスはクライアントの値を信用せず、サーバーでも線のデータから再計算して照合する。

### 第 3 段階

リアルタイムのオンライン協力・対戦。ホスト権威型。ホストだけが BT と波を動かし、位置と HP を配る。接続は GodotSteam の Steam Networking 中継。

## 不適切な絵への対応（第 2 段階で必要）

1. フレンド限定の共有には判定を入れない。公開ギャラリーとランキングだけを対象にする。
2. 公開申請時にサーバー側で線を画像に描き出し、分類 API で明らかなものを弾く。文字入力は名前欄だけにし、禁止語で弾く。
3. 一定数の通報で即座に非表示にし、あとで目視で確認する。
4. ユーザーが少ないうちは審査後公開にする。増えてから自動化の比率を上げる。

## Steam までの段取り

- Steamworks パートナー登録（1 タイトル 100 USD、売上 1,000 USD 到達で返金）。税務・銀行情報に数日かかるので早めに。
- ストアページは発売の 2 週間以上前に公開が必要。「近日登場」ページを縦切り完成の時点で出し、「絵心不要」「友達と一体を作る」「AI 不使用・オフライン可」を前面に、日英同時で出す。
- 体験版は 2027 年 2 月の Next Fest を目標にする。開始前にウィッシュリスト 1,000 件を超えておく。
- 価格は $9.99〜12.99（日本では 1,200〜1,800 円）。買い切り + 任意の DLC。
- ビルドは Godot の Linux / Windows エクスポートを SteamPipe で上げる。GL Compatibility レンダラーなので Steam Deck や古い PC でも動く。

## いまの試作でできること

- 描画フェーズ: 左右 2 枠に P1（からだ）と P2（ぶき）が同時に描く。パッド・キーボード・マウス。インク予算あり。元に戻す、完了、60 秒の制限時間。描画中にステータスと武器判定を表示。
- 合体演出のあと戦闘へ。線のデータは `GameSession` 自動読み込みで受け渡す。
- 生き物（`Beast`）は線から見た目（線を太らせた多角形）・当たり判定（凸包）・ステータス・武器を導出し、BT で敵を追って戦う。
- 敵・拠点・ローカル 2 人・無限ウェーブ・HUD は従来どおり。ゲームオーバー後は描き直しへ戻り、前の絵が残った状態から編集できる。
- 見た目はアートディレクション節のとおり（はかり野の世界観、ピクセルアート風の後処理）。押し出しの立体化は未着手。

敵と味方の生き物は同じ BT と同じ「移動・攻撃・被弾」の契約で動く。味方 CPU も同じ仕組みで作れるので、一人のときは CPU と協力できる。

## アートディレクション

参考画像は `docs/moodboard/`（2026-10-15 共有）。ゲームには同梱しない。

**世界観: はかり野 — よみがえりの大地。** 神々の世界が終わったあと、緑によみがえった巨人の骨の大地。
草の中から金の駒を見つけた人々（かたち読み）が、世界のかたちを読み直していく。

ゲームの仕組みとの対応:

| ゲームの要素 | 世界観での姿 |
|---|---|
| プレイヤー | 「かたち読み」の旅人。つば広の帽子、外套、背負い袋、ランタン付きの杖。旅人 1 は青、旅人 2 は琥珀の襟巻き |
| 描画フェーズ | 夜の机の上の「記録帳」。羊皮紙のページにセピアのインクで描く。羽根ペンのカーソル、インク壺、ろうそくの時計、封蝋 |
| 描いた生き物 | 「よみがえりの獣」。石と骨のかたまりで、描いた線が金継ぎの継ぎ目として光る。苔がつく。目などの内側の閉じた形は暗い空洞 |
| 合体 | 線が金に変わり、「かたち、よみがえる」。戦場では空から降りて「よみがえれ！」 |
| 敵 | 「霜の獣」。背を丸めた灰青の獣で、背中に霜の結晶。後半の波は赤い結晶の硬い個体。倒すと「パキン」と砕けて霜が地面に残る |
| 守る対象 | 刻む者の石碑の上に浮かぶ「金の駒」（正二十面体）。傷むと石碑に霜とヒビが広がり、駒が凍っていく |

**画面のつくり:**

- 戦場は奥に遠景（夕暮れの空、霞んだ世界樹、山並み、湖、針葉樹、霧に溶ける巨人の肋骨、錆びた大測輪、石碑、飛ぶワタリガラス）、手前に苔の草地（白い小花、紫の花、苔むした石、柵とカラス、半分埋まった骨、錆びた車輪）。すべて手続きで描いている（`src/fx/backdrop.gd`、`src/game/arena_decor.gd`）。
- 世界にはピクセルアート風の後処理をかける（`assets/shaders/pixelate.gdshader`、3 px のマス、色の段階を減らしてベイヤーディザ、暗部を青く明部を暖かく）。文字・HUD・擬音・ダメージ数字はその上の層に描き、くっきり読めるようにする。
- 光は加算合成（ランタン、金の駒、獣の金の線）。夕暮れの暗さの中で金が目を引く配色。
- 文字は Zen Old Mincho（明朝、SIL OFL）。見出しは Black、本文は Bold。情報の板は暗い地に金の細い縁と四隅の菱形。

**色:** `src/fx/doodle_style.gd` に集約。夜 #1c2130、灰青 #3f4a5e、霧 #a7aebb、骨 #d6cdb6、苔 #5d6834、石 #6b6c66、錆 #8a4f2e、暗い赤 #7a2f2f、金 #d9ad4f、ランタン #f4b65c、霜 #d6e8f0。

**手触り（ジュース）:** 画面揺れ、ヒットストップ（ハンマーは長め）、武器ごとの擬音、ダメージ数字、金の光の筋と砕片、獣の降臨、合体の金のフラッシュ、波の開始の帯、カウントダウン。

**題字:** 製品名は「はかり野」（2026-10-16 決定）。副題「よみがえりの大地」。リポジトリ名とプロジェクトの内部名は Doodle Beasts のまま。

**今後の見た目の課題:** 旅人と獣の手描きドット絵への置き換え（いまは手続きの図形）、押し出しによる立体化、昼夜や天気の変化、ストア用カプセル画像とトレーラー。音は手続き合成の仮素材なので、作曲家への依頼も検討する。

## 技術メモ

- 物理レイヤー: 1 = players, 2 = enemies, 3 = core。
- 座標系は 1280x720 固定、`canvas_items` ストレッチ。
- 入力は `src/game/input_setup.gd` が起動時に InputMap へ登録する。
- 乱数は `WaveManager.random_seed` で固定できる。
- 絵のデータは「線ごとの点の列」を正とし、ステータスも立体化もそこから毎回導出する。保存・共有・検証がすべてこの一つの形式で済む。
